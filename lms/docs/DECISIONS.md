# DECISIONS.md — append-only log

Format: date · decision · why · alternative rejected.

- 2026-07-28 · Requirements source is the ten Drive build docs vendored in `docs/build/` (00–09); the repo root's older `docs/` course material (Mission Room concept, prior assessment system) is ignored as stale · The user directed this explicitly; the Drive folder supersedes it · Rejected: treating repo course docs as requirements.
- 2026-07-28 · Realtime voice transport is LiveKit Cloud + LiveKit Agents (Deepgram → Gemini Flash → ElevenLabs) · Build prompt §2 and most of §6 pin LiveKit; a single leftover sentence in §6 says "OpenAI Realtime API" — treated as a drafting artifact · Rejected: OpenAI Realtime API.
- 2026-07-28 · Gate propagation via short-poll (3–5s) behind a client hook, not SSE · Identical UX at classroom timescales, no long-lived connection management on Railway, trivially load-testable; hook isolates a later SSE upgrade · Rejected: SSE for v1.
- 2026-07-28 · Near-duplicate detection uses content hash + Gemini embeddings (pairwise cosine within an assignment, in-memory) · Anthropic (the pinned grader) has no embeddings endpoint; the Gemini key already exists in the pinned voice stack · Rejected: adding a new embeddings-only vendor or pgvector in v1.
- 2026-07-28 · Role/section truth flows roster-row → Clerk publicMetadata (webhook pushes), never the reverse · First-sign-in Clerk accounts have empty publicMetadata; the reverse direction would overwrite imported roles · Rejected: Clerk-to-local mirroring.
- 2026-07-28 · Review-queue percentile trigger computed at queue render + batch finalise, not at grade time · Grade-time snapshots misflag early grades and miss late-context outliers · Rejected: grade-time percentile snapshot.
- 2026-07-28 · Sector claiming stays in the Praxel_MU_Sector_Tracker sheet for v0; the LMS stores each team's claimed sectorName (seeded from the 80-sector board) · Per 09_sector_board_80.md · Rejected: building a claiming UI in v1.
- 2026-07-28 · Grading eval bands are consistency checks, not accuracy ground truth · Bands are self-authored until MU digital-fluency calibration data arrives; instructor spot-validation of real early grades required before first batch-finalise · Rejected: treating a green eval as proof of grading accuracy.
- 2026-07-28 · Prisma pinned to v6 (6.x), not v7 · Prisma 7 removed `url = env(...)` datasource config (needs prisma.config.ts + driver adapters); v6 matches the pinned stack shape exactly · Rejected: Prisma 7 migration mid-scaffold.
- 2026-07-28 · Roster gate lives in `proxy.ts` (Next 16's middleware successor), not `middleware.ts` · Next 16.2 proxy files always run on the Node.js runtime, so Prisma works; Next 16 rejects a `runtime` segment config in proxy files (E1031), so no explicit runtime export is needed or allowed · Rejected: `middleware.ts` + `export const config = { runtime: 'nodejs' }` (the pre-16 pattern).
- 2026-07-28 · Off-roster Clerk accounts are flagged (privateMetadata.flaggedForDeletion + AuditLog), never auto-deleted · Deleting on webhook/proxy would destroy evidence and make a roster-data mistake unrecoverable; deletion stays a manual admin action · Rejected: `clerkClient.users.deleteUser` on unknown email.
- 2026-07-28 · Test-login backdoor requires NODE_ENV !== 'production' AND ENABLE_TEST_LOGIN, plus an instrumentation.ts boot assertion that throws if the flag reaches production · A single env flag is one misconfigured deploy away from an open door · Rejected: flag-only guard.
- 2026-07-28 · All server-side Clerk access goes through `lib/auth/` (dynamic imports), with explicit no-keys detection: proxy passes through and sessions resolve via the test-login cookie when Clerk keys are absent · Lets vitest/seed/Playwright and keyless local dev run without Clerk · Rejected: importing `@clerk/nextjs/server` directly in routes/components.
- 2026-07-28 · Migrations run in the web container's entrypoint (`docker-entrypoint.web.sh`: `prisma migrate deploy` then `node server.js`), with the Prisma CLI npm-installed globally in the runtime stage · Keeps deploy a single step; a failed migration fails the healthcheck and the previous deploy keeps serving; flat npm -g install avoids copying pnpm's symlinked node_modules into the standalone image · Rejected: Railway pre-deploy command (config drift across per-service files) and shipping the full builder node_modules.
- 2026-07-28 · Railway config-as-code is one file per service (`railway.json`=web auto-detected, `railway.worker.json` set via dashboard config path, `agent/railway.json` auto-detected at its root dir) · Railway has no multi-service config schema; web/worker share the `lms` root so only one can be auto-detected · Rejected: inventing a multi-service railway.json.
- 2026-07-28 · Worker image is single-stage, runs TS via tsx, `PLAYWRIGHT_BROWSERS_PATH=0` so Chromium lives in node_modules · Worker needs devDeps (tsx) anyway; no tsc build step to maintain; browsers-with-install survives any future stage copy · Rejected: tsc compile + prod-only multi-stage image.
- 2026-07-28 · Agent maps GEMINI_API_KEY → GOOGLE_API_KEY at boot (livekit google plugin reads the latter) · One canonical env name (GEMINI_API_KEY) across all three services · Rejected: requiring both names in Railway.
- 2026-07-28 · Gate resolution rule encoded once in `effectiveGateState`: open iff state==open OR (state==locked AND opensAt<=now); closed always stays closed (a manual toggle beats a schedule); missing row = locked · One function every consumer shares means no drift between hubs, dashboard, snapshot endpoint and console · Rejected: a background job materialising scheduled opens into state flips.
- 2026-07-28 · Per-student reopen is a new `GateException` table (forward-only migration `gate_exception`), unique (targetType,targetId,userId), honored by `resolveGate` when a userId is passed; an unexpired exception overrides both the target's own gate and its parent session gate · The schema had no exception mechanism; abusing AuditLog or ConfigKV as state would make resolution unqueryable and unindexed · Rejected: storing exceptions in ConfigKV/AuditLog, or widening Gate with a userId column (would break the per-section uniqueness).
- 2026-07-28 · Live propagation: `useGatePoll` polls `/api/gates/state` every 4s (paused while the tab is hidden), compares a sha1 content-hash `version`, and calls `router.refresh()` on change so server-component hubs re-render with fresh gates · Cheapest correct path to the ≤5s target; `ifVersion` short-circuit keeps idle polls to a tiny JSON body · Rejected: client-side gate rendering (duplicates resolution logic) and SSE (already rejected earlier).
- 2026-07-28 · Unlock Console close-with-pending confirmation is server-enforced: `/api/gates/set` refuses to close an assignment gate (single or session-bulk) while draft submissions exist in that section unless `confirmed:true` · A purely client-side confirm could be bypassed by a second console or a stale tab · Rejected: client-only window.confirm.
- 2026-07-28 · SSRF guard (`lib/net/safe-fetch`) validates resolved DNS addresses then fetches by hostname with manual, re-validated redirect hops (cap 3) — pragmatic v1, accepting the small lookup→connect TOCTOU window (documented in-module) · True IP-pinning needs a custom undici dispatcher; not worth it for a link checker + crawler in v1 · Rejected: custom Agent with pinned IPs.
- 2026-07-28 · Link-check rate limit is an in-memory per-user token bucket (~10/min) · Simplest thing that stops abuse from one browser; on multi-instance Railway the effective limit is N×10/min, acceptable for a HEAD-only checker · Rejected: shared-store (Postgres/Redis) rate limiting in v1.
- 2026-07-28 · Resubmission = a NEW Submission row at version+1 (history preserved, latest-version reads use orderBy version desc); contentHash = sha256 of canonical-JSON {fields, sorted files} written at submit time for U9 near-dup checks · Mutating rows would destroy grading history and break the matrix/version chips · Rejected: in-place update with a versions JSON column.
