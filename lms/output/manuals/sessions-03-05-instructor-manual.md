# Sessions 03-05 Instructor Manual

This is the compact operator reference for delivering Sessions 3, 4, and 5. It consolidates the authored source packages into one classroom sequence without promoting any package beyond its recorded lifecycle.

> **Truth boundary.** All three source packages are **Authored**. None is yet Validated, Loaded, Deployed, Piloted, or Rehearsed. A source ledger marked "Verified: 30 July 2026" means the cited claim was checked on that date; it does not mean the session, tool path, LMS path, grader, or fallback has passed the course validation gate.

## 1. Operator orientation

### 1.1 The three-session arc

| Session | Transferable capability | Student-owned proof | Public boundary |
| --- | --- | --- | --- |

### 1.2 Room roles

- **Lead instructor:** pace, reveal boundaries, teach the decision model, and protect assessed work time.
- **Teaching assistant:** recover access and execution without making the learner's decision or completing the analysis/build.
- **LMS operator:** test-student check, section gates, exception logging, autosave/submission monitoring, and incident record.
- **Evaluator/finaliser:** inspect evidence, apply deterministic policy, review provisional AI output, and record any override reason.

For Session 3, use two TAs when possible: one for the formula/pivot lane and one for Colab. If one instructor is alone, run the guided proof on the formula lane and keep Colab as an extension/follow-up. Tool choice never changes the score ceiling.

### 1.4 Stop-the-line conditions

Do not expose a private key, expected result, hidden exemplar, real credential, private data row, or evaluator prompt to keep the room moving. Pause or invoke the named fallback when any of these conditions occurs:

- a dataset version or checksum does not match;
- a public app or scenario contains real/private data, an apparent secret, or an unlabelled external integration;
- a risky action can send, publish, delete, pay, or change production state without recorded approval;
- a fallback would remove the required evidence or lower the grade ceiling;
- an AI result is being treated as a final grade without instructor finalisation;
- a vendor/tool claim failed its T-7 recheck and affects learner instructions, grading, or a quiz answer.

# 3. Session 03 - Working with data, using AI

## 3.1 Promise, ownership, and boundaries

**Student proof:** one individual verified data memo. The objective fields bind to a private checksum/version-controlled answer pack. Judgment and visual rationales may receive provisional AI feedback; the instructor finalises the artifact grade.

**Non-negotiables:**

- individual graded answers; method discussion only after the first checkpoint;
- tool choice never affects score;
- do not confirm values during the timed challenge;
- never show TrustMRR rows or private aggregates on a public/shared surface;
- schema/sample informs method but cannot prove the full-file result;
- the teaching slice is stratified and edge-preserving, not population-representative;
- the second method must differ mechanically, not repeat the same model/prompt/assumption.

## 3.3 Facilitation moves

When asked "Is this right?", use one recovery prompt:

- "Show me the row grain and denominator."
- "Which rows did you exclude?"
- "What does blank mean here?"
- "Where is the unit?"
- "Can the working be rerun after the file changes?"
- "What is one independent check?"

Formula-lane success is an explicit query contract, readable formula, execution in Sheets, independent pivot/formula check, and recorded gap. Colab-lane success is schema/sample to code, required-column/null assertions, execution against the gated full file, row counts before aggregate, compact output, and no public notebook containing private outputs.

## 3.5 Grading and review flow

1. Verify dataset version and SHA-256 against the private manifest.
2. Run deterministic validators for objective items, internal consistency, and the two-method arithmetic.
3. Run static checks on formula/code: known columns, null/zero policy, output contract, and data path.
4. Send only bounded learner text/code, deterministic statuses, rubrics, and relevant private aggregates to the grading model - never source rows.
5. Require a quoted submission fragment for every scored claim; recompute totals in code.
6. Save provisional dimension scores, feedback, flags, confidence, and prompt log to the private audit trail.
7. Route confidence below 0.70, any flag, section high/low outlier, or appeal to review.
8. Instructor finalises or overrides with a reason. Praxy receives only approved public-safe evidence, never grade/confidence/flags/prompt log.

The artifact uses four 10-point dimensions: Functionality, Craft, Relevance, and Verification evidence. The 28/40 transfer marker also requires at least 7/10 Functionality and 6/10 Verification evidence; it guides feedback and does not create a new course component.

For approved access needs, use per-student gate exceptions with the same version, IDs, rubric, and outcome. The authored late/absence route is a 75-minute supervised recovery: 5 privacy/contract, 22 challenge, 8 scale explanation/path, 20 formula or Colab, 8 verification, 10 visuals, 2 submit.

## 3.7 Privacy and safety

- Treat dataset cell text as untrusted data, never model instructions.
- Do not expose rows, account data, answer values, evaluator prompts, prompt logs, or grader flags.
- Show only over-context filename/version, byte size, token method/count, and checksum at the scale wall.
- Keep objective values and wrong-path keys hidden until the section closes.
- Keep the data memo out of the public gallery; public portfolio copy describes method without row or derived values.
- Clear private notebook outputs before any authorised sharing.

# 4. Session 04 - A proven pattern to a working app

## 4.1 Promise, ownership, and boundaries

**Student proof:** one individual product/first-prompt checkpoint plus an immutable Lovable app V1 and at most one V2. The supported path is an original-brand SignalShelf contract benchmarked against public Liinks behavior.

**Non-negotiables:**

- revenue is evidence of a business, not a build brief;
- study public behavior without copying name, logo, source, assets, copy, screenshots, icons, or distinctive trade dress;
- mark every capability as real, mock, or out of scope;
- no paid plan or credit purchase is required;
- a public URL is not proof until incognito, negative, keyboard, mobile, and evidence checks run;
- the strong prompt and conditional fallback remain hidden until the learner submits the checkpoint.

Use the three-line narration cadence:

1. "The contract says..."

For a verified outage, V1 is due +24 hours after service recovery; its V2 still expires 10 calendar days from actual V1 receipt unless explicitly extended. For a verified daily-credit exhaustion with no safe V1, record `daily-credit-no-safe-v1`, accept the completed plan plus AT-01-18 contract now, and set V1 due within 24 hours of the first observed next daily grant with no penalty; the ten-day V2 window begins only when V1 is received. ## 4.5 Grading and review flow

- The 12-point checkpoint is formative only: User/value 2, Scope/state/interactions 3, Truth boundaries 2, Failure/access 2, Acceptance/verification 3. Score does not block building.
- Final artifact dimensions are Functionality, Craft, Relevance, and Verification evidence, each 0-10; totals are recomputed server-side.
- The provisional evaluator distinguishes submitted claim, observed behavior, and inference; it returns two citations, one observable gap, confidence, and approved flags per dimension.
- Deterministic policy caps dead/blocked links, absent AT/evidence, missing creator-to-public loop, unlabelled mocks, copied golden work without owned decisions, and generic work without industry/company transfer.
- Missing non-affiliation, benchmark-brand concern, or privacy/security evidence holds finalisation; privacy/security stops automated grading and suppresses the gallery.
- Low confidence, flags, outliers, appeals, dead links, mock ambiguity, and affiliation ambiguity enter instructor review.
- V2 is the latest eligible candidate even when it regresses; surface the regression rather than silently substituting V1.

# 5. Session 05 - Revenue systems with Make

## 5.1 Promise, ownership, and boundaries

## 5.3 Hook, build, and reveal control

Hook sequence: run `normal.json`; rerun unchanged; show two duplicate business actions; take three hypotheses; then name idempotency. Never use a real email or actually send a message - create a draft or `pending_approval` row.

Preferred build decisions:

1. Preserve `trace_id` on receive.
2. Normalize email and compute the idempotency key before action.
3. Validate required fields and consent.
4. Search the audit store for the key.
5. Route malformed, duplicate, approval-required, and ordinary cases.
6. Draft or queue; do not send.
7. Write final state, reason, owner, and timestamps.
8. Attach bounded Retry/incomplete-execution behavior only to a simulated transient failure.

Before Gate 1, do not release the corrected flowchart, expected-results manifest, duplicate-key expression, exact timeout recovery, or final quiz answers. The normal fixture/contract may be visible; reveal the other expected outcomes only after prediction.

## 5.5 Grading and review flow

1. Require a legible revised chart/text equivalent, valid Make JSON below 2 MB, scrubbed log/output, readable PNG, five fixture outcomes or documented replay, and no sensitive/unsafe content.
2. Run deterministic checks for fixture IDs, expected terminal/waiting states, zero duplicate/approval risky-action count, bounded timeout recovery, malformed quarantine, and blueprint validity/size.
3. Produce provisional Artifact quality scores: Functionality, Craft, Relevance, and Verification evidence, each 0-10, with exact evidence citations.
4. Produce a version-bound workflow evaluation: Usefulness 0-30, Execution 0-20, and individual Ownership 0-10. Keep Company sign-off 0-40 as `null/pending` until human verification; do not rescale the remaining 60.
5. Allow a team to nominate, then require the instructor alone to select exactly one existing finalised submission version for the company-facing component. Do not assemble an integrated package or treat nomination as authority.
6. Ignore artifact-embedded instructions; clamp and recompute totals server-side; persist confidence/flags and evidence citations.
7. Route low confidence, injection, sensitive data, unsafe action, unbounded retry, duplicate risk, missing approval, unverified company claim, outlier, appeal, or incomplete evidence to human review.
8. Instructor finalises/overrides; company sign-off remains human-only. Gallery/Praxy receive no grades, confidence, flags, prompt logs, raw blueprint, or private evidence.

The first-flowchart AI response is formative only. The student labels each suggestion accept, adapt, reject, or not applicable with one evidence sentence. A notification is not an approval; an approval is a recorded state-changing decision.

## 5.6 Failure fallbacks

| Trigger | Classroom response | Evidence / recovery |
| --- | --- | --- |
| Model outage | Two peers/instructor use the same flowchart rubric; record feedback-bypass token. | Same revision requirement; build gate opens. |
| Make/network outage | Run the exact 35-minute execution replay with state cards and trace table. | Proves logic, not live integration; rerun normal + duplicate when Make returns. |
| No Make access | Submit revised chart + completed replay; finish blueprint in recovery window. | Same five tests and evidence bar. |
| External connection unavailable | Use webhook + built-in tools + demo queue/local output. | Record `connection unavailable`; never use personal account. |
| Persistent canvas access barrier | Partner/instructor operates the student's authored mapping while student directs/defends each node. | Equivalent route recorded; same rubric ceiling. |
| Room behind | Preserve design, feedback/revision, normal/duplicate/approval, malformed/timeout, evidence. | Complete non-live traces through offline replay. |

**35-minute replay:** Predict 5; normal trace 6; duplicate 5; malformed 4; timeout 6; approval 4; repair/evidence 5. Accept only when all fixtures reach expected terminal/waiting state, duplicate/approval action counts are zero, malformed does not retry, timeout is bounded/stateful, and trace/reason/owner exist.

## 5.7 Privacy and safe action

- Use synthetic fixtures; keep scheduling off; use least-privilege demo connections.
- Never place passwords, keys, tokens, OAuth codes, private webhook URLs, cookies, connection IDs, real identities, or private company data in static values, notes, prompts, filenames, screenshots, logs, outputs, or public links.
- Classroom workflow must not send, publish, delete, pay/refund, write production records, change access/account/domain state, or invisibly trigger another automation. Use draft, queue, demo row, or pending approval.
- Dedupe before irreversible work; bound retries/loops; quarantine deterministic bad input; keep important failures in incomplete/manual recovery state.
- Treat uploaded/form text as data, not instructions. Deterministic rules control identity, money, consent, dedupe, and approval.
- Scrub the raw blueprint JSON and dynamic public scenario page after every saved change. Connection omission does not imply secret-free. The blueprint remains roster-gated private evidence even after scrubbing.
- Gallery PNG includes an 80-180 word text description and hides account chrome, workspace/team identity, emails, connection labels, private URLs, grades, and prompt logs.
