## Session promise

Students will turn evidence about a proven product into a lawful, original-brand feature contract; use one high-quality Plan-mode prompt to direct Lovable; ship a public Version 1; and prove what works with acceptance-test evidence. A credit-budgeted Version 2 may replace Version 1 within the ten-day follow-up window without erasing the original evidence.

The frozen instructor build candidate is **Liinks**, a creator link-page builder. Its public evidence supports the direction; the 96/100 feasibility score remains provisional until the fresh-Free golden run and mixed-confidence dry run pass. The classroom build is **not** a Liinks replica. It uses the working title **SignalShelf** and recreates an agreed functional pattern with original naming, copy, visual design, and demo data. It is not affiliated with or endorsed by Liinks, TrustMRR, or Lovable.

## Release dependencies

Before this package can be labelled **Validated**:

1. pass the predeclared Liinks release gate in `03-product-selection-scorecard.md`: fresh Lovable Free golden run plus at least four mixed-confidence dry-run learners;
2. record actual per-message credit use without turning the observation into a promise;
3. pass every acceptance test—including S4-SP-1 malformed, tampered, oversized, unsupported-version and invalid-schema cases—on desktop, mobile, keyboard-only and incognito;
4. verify the no-formal-Plan branch and zero-credit starter/restore behavior in the current Lovable UI;
5. calibrate at least two graders on the three anchor submissions and run S4-GF-01–06;
6. test the 12-point variable-max checkpoint grader, 40-point final grader, caps, two-citation output and finalisation holds;
7. test the V1 → V2 and monthly-cap exception paths; confirm V1 remains available and no learner can create V3;
8. prepare a captioned build recording, static screenshot pack, and a tested fallback starter;
9. repeat the source checks in `source-ledger.md` at T-7;
10. confirm all public examples use dummy identities, links, emails and analytics.

## Instructor boundary

“Complete” in this session means **complete against the published classroom contract**, not parity with every capability of a mature commercial product. Liinks currently exposes a much broader surface—including many block types, audience management, richer analytics, custom domains, multiple profiles, and an API. Students must label every omitted or simulated boundary and must never claim production parity.
