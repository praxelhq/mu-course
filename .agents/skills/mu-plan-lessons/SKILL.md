# MU Lesson Planner

Design a repeatable, high-agency lesson for eight sections and a mixed-skill PGP cohort.

## Resolve inputs

Read, in order:

1. `lms/docs/build/SOURCE_OF_TRUTH.md`;
2. the active session brief;
3. COT v3 and the scoring methodology;
4. the immediately preceding delivered deck/materials so the bridge is accurate;
5. `lms/CLAUDE.md`, current AssignmentTypes, submission schema, gates, and gallery behavior when LMS evidence is involved;
6. relevant current vendor documentation for volatile tools, dated at authoring and checked again at T-7.

For Sessions 3-5, `10_sessions_3_5_redesign_brief.md` replaces the root lesson packages and the original Moxie/stocks Session 3 lab.

## Plan backward from evidence

1. Write three to five observable outcomes, each tied to a real task.
2. Define the exact evidence field/file/link that proves each outcome.
3. Separate correctness, judgment, verification, and ownership.
4. Design the student work and failure/reveal before the explanation.
5. Use the Operator's Loop explicitly where it helps students act.
6. Choose the smallest demo that makes the method visible.
7. Map the work to an existing grade component; do not invent new weights.
8. Keep stream relevance course-wide unless a role-specific choice genuinely changes the data, decision, or evidence.

## Use the 120-minute rhythm

Include:

- arrival/retrieval or prediction;
- a consequential hook;
- concise concept and live proof;
- guided build;
- independent challenge or staged reveal;
- verification and repair;
- submission/feedback moment;
- reflection, portfolio capture, and next-session bridge.

Protect at least 60 minutes for student work. State exact timings but allow the instructor to compress discussion rather than the assessed build. Include:

- supported path for non-technical students;
- extension path that does not raise the core grade ceiling;
- network/model/tool-credit fallback;
- accessibility-equivalent route;
- instructor-only answer/reveal boundary;
- late/absent learner recovery;
- multi-section calibration note.

Model staged work explicitly. Session 4 requires a first-prompt/product checkpoint, Version 1, and a controlled Version 2 follow-up. Session 5 requires flowchart feedback before blueprint/log/gallery evidence.

## Output

Produce:

- session promise, prerequisites, materials and environment check;
- measurable outcomes and evidence map;
- minute-by-minute run of show;
- instructor demo script and debrief questions;
- student task/build brief;
- checkpoints, likely misconceptions, and recovery prompts;
- exact LMS gates, assignments, fields, feedback, resubmission rules, and gallery behavior;
- grading/rubric link and exemplar boundaries;
- after-class follow-up and portfolio action;
- lifecycle status and release dependencies.

Hand content production to `$mu-create-course-materials`, genuine branching simulations to `$mu-design-simulators`, assessments to `$mu-create-quizzes`, LMS deltas to `$mu-design-lms`, and the full session to `$mu-validate-learning-assets`.
