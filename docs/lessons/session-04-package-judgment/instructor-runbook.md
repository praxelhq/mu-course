# S04 Instructor Runbook — Package Judgment v1.0

**Audience:** lead + support facilitator. **Class:** ~60. **Do not teach prompt tricks.** The emotional arc is confidence → embarrassment at the mega-prompt → control → peer exposure → earned repair.

## Setup (48–72 hours)

Freeze runner and fixtures; test all eleven packs; print one packet per learner plus 15% spare; seal hidden cards; load golden/developing/unsafe anchors; verify keyboard, screen reader, large print, offline logging, section-specific hidden variants, and no real PII. Seat clean-run pairs across different project contexts. Never reveal hidden fixtures in slides.

## Facilitation prompts

“What event invokes this?” “Which field is required to decide?” “Could a formula do this step?” “What must it decline?” “What evidence proves your change fixed the layer?” Never edit a learner prompt for them.

## Misconception interventions

Long generic prompt → demand one job and non-trigger. Missing data inferred → turn into explicit `needs_input`. Perfect schema/generic judgment → ask for a counterexample. Refusal treated as weakness → compare prohibited action count. Model variance → score properties, retain one versioned run.

## Section consistency and alerts

Use only assigned pack/variant versions. A facilitator override needs reason + evidence ref. Heat map: missing prediction, over-broad trigger, fabricated field, failed clean run, hidden repair stall, safety quarantine, incident route. Do not rank speed, code, prompts, or prose polish.

## Debrief (three questions)

What did the mega-prompt know that the method made explicit? Why was a safe stop a successful run? Which layer will become an event-driven control in Session 5?
