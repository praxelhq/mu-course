# S04 Accessibility and Reliability Route v1.0

## Equivalent supported route

All input, output, errors, demo content, and hidden changes exist as structured text. Core flow is keyboard operable with visible focus and semantic labels; errors name field, cause, and recovery, not color. 200% zoom, screen-reader table alternative, reduced-motion, high-contrast print, and written peer/defence routes are supported. No voice, public posting, rapid typing, drag, or coding is assessed.

## Low-bandwidth/offline

Use printed Method Contract, numbered executor cards, fixtures, peer log, sealed hidden change, deterministic answer card, and facilitator receipt. The assessed evidence is identical: prediction, contract, normal/messy/non-trigger, independent run, defect, hidden repair, rerun, boundary. Upload may occur later with incident ID and original timestamp.

## Activation

Learner may pre-select the route; facilitator may activate for outage/device/model/access issue without requiring medical disclosure. Extra-time learners receive equivalent variant and pause/resume; reveal integrity is preserved. Pair-device support must retain independent executor identity. Platform/model unavailability is status `unavailable`, never `fail`.

## Safety fallback

If personal/confidential data appears, stop display, quarantine the artifact, switch to matching synthetic fixture, record incident without copying sensitive content, and continue. Human support handles any accessibility or safety dispute; evidence bar remains unchanged.
