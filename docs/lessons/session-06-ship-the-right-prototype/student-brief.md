# S06 Student Build Brief — Form Follows Work v1.0

## Role and stakes

You are releasing Prototype v1 for a fresh assigned role-card tester. Your goal is not to build “an AI app.” It is to make one professional task usable, observable, and bounded.

## Choose and reject

Select the smallest appropriate surface: app/form, workflow/control surface, grounded assistant, dashboard/model, data surface/pipeline, or necessary combination with one entry path. Name one tempting form you reject and why.

## Commit before building

1. Core success test: fresh user completes ___ and produces ___ evidence.
2. Safe-failure test: invalid/unsafe input results in ___ and no ___ action.
3. Observability test: attempt log contains input/version/result/validation/human action/time.

## Build and test

Connect or replay S04 method + S05 control; implement one human decision/next action; instrument start/result/failure/approval; self-test the supplied normal and boundary cards; freeze. The assigned tester then receives the section-salted changed/unsafe card, hidden from the author until the attempt ends. Classify the observed issue, make one bounded repair or hold with an exact repair specification, and rerun the affected/equivalent test.

## Definition of done

Reachable or replayable core task under three minutes; valid structured input/output; visible error/recovery; inspectable log; fresh attempt; safe boundary; disclosure; no secrets/PII; release note. Submit URL/replay, version refs, tests, attempt, observation, diff/decision, provenance, accessibility note. Independent educational project; no employer affiliation or private data.
