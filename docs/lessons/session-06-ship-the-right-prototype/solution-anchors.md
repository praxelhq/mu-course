# S06 Solution and Scoring Anchors v1.0

## Common 70%

Verified: role-fit chosen/rejected form; tests precommitted; one core task works via linked method/control; fresh tester succeeds; safe failure performs zero prohibited action; run is observable; issue decision cites evidence; affected rerun; disclosure/provenance/accessibility. Pass: usable bounded task + safe failure + independent trace, with minor repair. Partial: author can operate but fresh user confused, instrumentation incomplete, or form weakly fit; no unsafe action. Fail: landing-page theatre, screenshots/page views, author-operated attempt, no boundary, or cosmetic acceptance. Unsafe: secret/PII, autonomous high-impact or external production action, deceptive affiliation, inaccessible-only release.

## Pathway 30%

Consulting: quantified pilot/implementation/client authority vs generic AI cockpit. FOCOS: explicit priority/non-priority/owner/risk vs summary dashboard. Product: user task/event/release fallback vs feature demo. IB: trace material input/scenario/exception/senior approval vs hidden-source memo. VC: evidence/countercase/IC input vs autonomous recommendation. Corp Fin: sensitivity/reconciliation/CFO decision vs magic forecast. HR: minimization/fairness/appeal/human control vs ranking assistant. Ops: SLA-cost-safety/idempotent operator recovery vs generic alerts. Sales: discovery/claims/consent/seller approval vs outreach generator. Marketing: insight/claim/hypothesis/valid metric vs asset generator. Data: metric/lineage/tests/uncertainty/decision cue vs pretty dashboard.

## Moderation

Most likely disagreement is form bias. Compare task completion, role fit, safe failure, observability and decision usefulness; do not reward a web UI over replayable workflow/model/data surface. Tester preference and visual finish are non-scoring. Safe, inspectable hold may outperform a flashy run.
